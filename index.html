详细介绍

以下内容介绍 3.0.0 原生客户端的页面结构、数据策略与设备体验。

01

HarmonyOS 原生客户端

Dashboard 应用看板是 harmony_get_market 的 HarmonyOS 原生客户端，当前为 3.0.0，面向 HarmonyOS 6.1（API 23）的手机、平板与二合一设备。它通过统一的 /api/v0 接口读取市场数据，并保留 S 站的 ArkWeb 入口。

主界面由四个固定栏目组成：S 站、首页、详情和“我的”。首页展示应用、元服务与最近收录；详情页提供概况和总表切换、搜索、字段筛选、排序与分页；所有入口复用同一原生详情模板，集中呈现应用信息、截图、介绍与下载量／评分趋势。

S 站会在启动时预热并缓存网页，可分享当前地址，并支持碰一碰、隔空传送和跨设备接续。原生详情也会生成带应用图标的分享卡片；接续时会恢复当前栏目、详情子视图与滚动位置。

02

可靠的数据访问体验

  • 统一 API 客户端：业务页面不各自拼接网络请求，全部使用一致的应用标识与错误处理。
  • 分层缓存：首页缓存 5 分钟、列表 2 分钟、详情与图表 30 分钟；有效缓存可直接读取，减少启动与切页等待。
  • 弱网回退：缓存失效后才访问网络；请求失败时最多可使用 30 天内的旧缓存，并明确标示离线缓存与缓存时间。
  • 可控清理：清除缓存会移除 API 文件、ArkWeb 存储和 Cookie，同时保留用户名及偏好设置，并显示缓存占用。
  • 响应式与无障碍：按 600vp、840vp 断点调整布局；核心控件、图表和提示均提供辅助功能文本。
⚠️

重要提示

  • 市场数据来自网络，仅供参考；不保证来源的准确性、完整性或实时性。
  • 应用会使用设备信息生成请求 User-Agent，并包含匿名运行遥测；具体处理以应用内隐私政策为准。
  • 缓存状态会在界面中明确呈现，离线数据不应被视为实时结果。
  • API 接入前请先联系项目组；取得的信息不得在本地原样存储。
🎨

鸿蒙版本特色

原生页面、跨设备接续与细致的系统交互

  • 全原生浏览：ArkTS + ArkUI 构建首页、搜索、总表与详情；S 站仅作为 ArkWeb 入口保留。
  • 连续体验：统一恢复主栏目、详情状态和滚动位置，S 站和详情页可分享、碰一碰与隔空传送。
  • 系统化交互：支持深浅色、高级材质、半模态联系面板、下拉刷新和可配置的触觉反馈。
  • 稳健易用：网络、文件、分享和可选设备能力均有回退处理，界面为关键内容提供无障碍描述。

技术架构

项目采用现代化技术栈，确保高性能、高可用性与可维护性

后端技术（Rust）

Rust 技术栈实现数据聚合、API 暴露、数据库访问和服务端能力编排

  • Rust 2024 Edition：内存安全、零成本抽象、高性能
  • Axum 0.8：类型安全的 Web 框架，ergonomic API 设计
  • Tokio 1.47：异步运行时，高效并发处理
  • SQLx 0.8：编译期 SQL 检查，类型安全的数据库操作
  • Reqwest 0.12：HTTP 客户端，支持连接池与自动重试
  • Serde + TOML：序列化/反序列化，配置管理
  • Tracing：结构化日志与性能追踪
  • Tower HTTP 压缩：Brotli、Gzip、Deflate、Zstd

数据库（PostgreSQL）

PostgreSQL 12+ 推荐 14+，强大的关系型数据库

  • 数据表：app_info, app_metrics, app_rating, app_raw, substance 等
  • 触发器：自动化数据更新与一致性维护
  • 索引优化：查询性能提升
  • 外键级联：数据完整性保障
  • JSON 字段：灵活的数据结构支持

网站前端

S 站前端

  • 原生 JavaScript：无框架依赖，轻量高效
  • Chart.js + Date-fns：数据可视化
  • Markdown-it：Markdown 渲染
  • 响应式设计：移动端适配

T 站前端

  • Vue.js：渐进式前端框架

鸿蒙前端

  • ArkTS：鸿蒙应用开发语言
  • ArkUI：声明式 UI 框架
  • ArkUI + HDS：原生导航、固定标签与响应式页面
  • ArkWeb：预热、缓存与 S 站入口
  • Stage Model + Hvigor：API 23 工程与构建工具链
